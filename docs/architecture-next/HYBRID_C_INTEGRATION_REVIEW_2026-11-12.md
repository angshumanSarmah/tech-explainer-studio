## Compatibility findings and conflicts

1. **Accepted architecture is preserved.** Hybrid planning stays inside the Director boundary. Future media provisioning is an explicit, approved operation before freezing inputs for the deterministic Producer; neither renderer nor Publisher calls a generator. No fourth autonomous agent, parallel renderer, editable compiled plan, source ledger or rights/job store is warranted. H1/H2 are new gates, not historical phase restarts.
2. **11D remains a data/planning phase.** Its original paid-image exclusion is intact. `AssetNeed`, `selection_required`, `needs_resource` and media consent states are proposed semantics, not implemented public types/flags. Strict `DirectorDraftSchema` and job `SnapshotSchema` currently have no unresolved resource fields. 11D must justify the smallest compatible versioned planning persistence extension; no fictitious asset IDs in render-ready VideoScript. H1 owns image resolution/generation; H2 owns clips.
3. **Costs and receipts are only partly implemented.** `ai_usage` imports completed Director receipts; it is not a transactional provider-payment ledger. DeepSeek retains conservative reserves in one adapter instance, with at most six transport attempts; draft receipts allow two candidates and six usage entries. Multi-stage planning cannot silently multiply these limits. H1 must implement durable item approvals, shared atomic reservations, ambiguous-outcome reconciliation and enforceable caps before media dispatch; H2 reuses that service. Extending a text provider interface into an unrelated universal media API is not required.
4. **“Asset Manifest” is conceptual.** Existing VisualAsset 1.0.0 has image identity, dimensions, source and rights review; it lacks duration, generation options/request receipts and costs. Release rights enums for stock/Lottie/Rive/3D/AI images are inventory extension points, not decoding or rendering implementations. H1 must choose an additive provenance representation preserving old record hashes; H2 additionally needs reviewed clip contracts and handlers. No duplicate manifest schema is introduced here. Current SVG handling rejects unsupported/active content; general sanitization/rasterization is not implemented and must not replace that fail-closed policy by implication.
5. **Portability extends working export/import.** Current `director export` emits schema/catalog/brand/example/prompts/request and a small hash manifest in a directory. It has no ZIP Kit, share-consent/redaction workflow, asset availability inventory or Kit-aware stale-version import. Generation schema is 1.2.0; outer `contractVersion` remains director-1.0.0 while prompt version is director-1.2.0. These are different identities, not permission to relabel saved drafts. Future Kit compatibility must use real digests plus runtime validation, not a guessed version string. Bare JSON remains supported without provider credentials.
6. **Historical readiness wording needs precedence, not rewritten history.** `ARCHITECTURAL_DECISIONS.md`, `COMPATIBILITY_AUDIT.md`, old execution order and some contract headings predate accepted/completed 11C. Old audit gaps (current-only draft prompt literal, asset collection limited to layered scenes, missing semantic fact invalidation, dispatcher parity) are now fixed in code/tests. The current status/closure controls engineering readiness. Original 11D still requires human schema/catalog/media review and multi-topic/holdout quality evidence: engineering acceptance does not silently waive those or authorize starting 11D. Its actual source count is already **one or more**; multi-source evaluation remains mandatory.
7. **Inherited prompt contradictions remain explicit.** The v6.1 Phase 12 addendum calls itself the “only new” delta; the new Hybrid companion is additional future scope, and the execution index requires all three files. Original 12's historical map/3D wording must resolve from the actual catalog: bounded SVG CityDemandHeatmap exists, general GPU 3D does not. The old 09 source-guided addendum's “private or unlisted test rules” conflicts with original 09's explicit private-only rule and `MetadataSchema.privacy = private`; **unlisted is not authorized**. No security gate or original prompt is weakened. Original 13's simpler-scene fallback must be an explicit revised input with review, consistent with ADR-019, never silent substitution. Phase 14's multi-source example does not revoke 11D's one-or-more input contract.
