## B. Decisions to lock before implementation

The proposed ADR specifies nine decisions: public VideoScript 1.2.0 additive branch; internal derived compilation; one registry/catalog; Phase 04 measured timing ownership; explicit compatible continuity; complete cache identity; Phase 08 invalidation ownership including visual semantics; one-or-more explicit source scope; and reuse of LLMProvider/manual flow. **None is accepted by this audit.** In particular, decide whether the first cut's outgoing terminal-pose overlap is sufficient; a continuously moving outgoing scene would require a different, explicitly tested frame contract.

## C. Narrow initial vocabulary and coverage

Proposed first cut: three base visual primitives, **node, link, token**. A node includes a literal label, optional finite status/highlight, optional approved local image reference and a semantic role; a link joins known entity ports; a token can follow one link or move to an existing layout slot. Flat groups and row/column/small-grid layout hints organize those primitives. Compiler owns pixel positions, cubic paths, fitting and draw order. Reuse existing Inter and semantic brand roles. No custom CSS, free-form SVG path/expression, network asset or topic-name dispatcher.

Start actions with appear/disappear, follow-link/move-to-slot, finite status/highlight, and bounded focus between registered views. Proposed caps to validate in 11C: 8 entities including tokens, 12 links, 16 actions, 2 simultaneous moving tokens, 2 flat groups (no recursion), 2 image-backed nodes, labels ≤24 characters/two lines; 12-frame transition preset that must fit both adjacent scenes. Existing scene/video/audio budgets remain outer limits. These limits are proposed engineering bounds, not measured capability promises. Crowding/unsupported action/representation returns typed scene/entity/path diagnostics; no automatic text-size reduction or title-card substitution.

This can illustrate authored request/cache handoffs, file/data transfer and small queue/dataflow stories. It cannot calculate cache correctness, emulate distributed consensus/Kubernetes, execute snippets, generate arbitrary graph layouts, show large crowds, infer physical causality, render live UI, import arbitrary models or deliver true 3D. Existing specialized queue/B-tree/Git/city components remain useful and do not count toward the generic composition demonstrations. Freeze inventory before selecting the unseen holdout; a coverage failure is evidence, not permission to add a handler during the test.

## D. Transition findings from code and saved output

**Supported conclusion:** the current engine changes the selected scene at an exact frame boundary, restarts local mechanism progress/entrance opacity, and relies on individually authored templates for continuity. There is no general overlap/continuity contract. This explains supported discontinuity mechanisms; it does not establish the cause of every historical video complaint.
