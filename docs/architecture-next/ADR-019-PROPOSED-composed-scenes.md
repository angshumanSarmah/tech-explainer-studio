# Proposed ADR-019 — Add bounded composition to the existing Producer

**Status: ACCEPTED by the user, 2026-11-11.** Recorded in [the existing ADR log](../15-adrs.md#adr-019--bounded-composition-and-shared-scene-continuity). The user explicitly accepted the amended decisions and separately authorized Phase 11C implementation. The filename is retained for stable references. The existing architecture audit remains unchanged evidence; no release approval or Phase 11D/12 authorization is implied.

## Context

The repository has strict VideoScript 1.0.0/1.1.0, deterministic Remotion/SVG components, local measured Kokoro audio, one sample/frame/caption timeline, bounded reviewed research, a provider-independent Director, fenced cached jobs and independent exact-artifact release gates. It selects one visual component per scene; some templates compose internal objects/images. It lacks a generic semantic composition grammar and generic boundary continuity. CityDemandHeatmap is a proved specialized SVG 2.5D path with an explicit flat fallback, not generic composition or GPU 3D.

## Reviewed architecture with required amendments

1. **One public authoring family.** Add VideoScript **1.2.0** with a strict `composed` visual variant containing stable entity IDs, finite semantic roles, relationships, layout hints and action/cue references. A separate scene-level boundary policy in 1.2.0 applies to compatible existing visual variants as well as composed scenes. Keep 1.0.0 and 1.1.0 accepted with their original rejection rules, defaults and pixels; retain the specialized variants. No automatic migration is needed for old scripts. An operator must explicitly create a revised 1.2.0 script to opt an existing specialized scene into a new transition. Do not widen the shared legacy SceneV1 or relabel historical scripts. Keep `VideoScriptV1` legacy and extend the general `VideoScript` union/version router and all consumers. Version-aware historical Director draft reads must survive prompt upgrades while preserving their original identities.

2. **Derived compiler output, never a second editable script.** A pure deterministic compiler inside the existing Producer resolves refs, finite layouts, geometry, paths, action tracks, camera and continuity from validated script, approved brand/assets and measured Timeline. Persist an internal `CompiledVisualPlan` with input digest, compiler/catalog/registry identities and diagnostics in the render tree. It has no LLM, source fetch, package installation or approval capability. The authoring schema retains intent/cue IDs; resolved geometry/frame ranges belong only in the derived plan. Keep compiler code inside currently fingerprinted renderer/domain trees or explicitly extend implementation hashing.

3. **One authoritative capability inventory.** Extend the current registry and attach static local handlers, rather than create an unrelated generic registry/catalog. Generate schema/capability metadata and Director export from the same descriptors, with browser-safe/static bindings. Registry IDs, executable actions, layouts, limits, examples and versions must agree in actual dispatch tests. The existing separately enumerated registered union/LibraryScene paths must have exhaustive parity checks. Unsupported capability returns typed scene/entity/path diagnostics; an explicit human-selected alternative is a new script revision.

4. **Phase 04 owns global time.** Preserve measured scene lengths `D_i = ceil(max(audioSamples_i/800, minSeconds_i*30))`, cumulative starts `S_i`, and total `T = sum(D_i)` at 30fps/24kHz. Preserve current safety checks for minimum frames, scene max duration and total duration. Resolve reviewed word/phrase or bounded progress anchors once into that epoch. No Director/UI/FFmpeg timer may override it. Existing scene-span fallback stays explicitly unreviewed; no new aligner or guessed word times.

5. **Generic basic continuity and composed object handoff.** Preserve intentional hard cuts. Add opt-in, bounded **basic visual crossfade across compatible scene types, including existing specialized templates**, plus matched-object handoff for compatible composed scenes with stable entity IDs. The executable registry declares content-layer/crossfade capabilities and compatible pairs; this is not a composed-only feature. Crossfade does not require matched entity IDs. Establish compatible specialized→specialized and composed↔specialized examples, and report unsupported pairs with typed scene-pair/path/reason diagnostics and explicit alternatives. Never silently replace a requested transition with a cut.

   Use the same Producer/Remotion composition and local component handlers to evaluate at most two content layers; add no second scene/video renderer. Default remains cut, and only explicitly revised scripts receive new behavior. For the initial short preset, at boundary `B = S_(i+1)` use `[B,B+W)` with `W=12` fitting both adjacent scene lengths. Hold the outgoing content's terminal pose while incoming content advances; interpolation uses `k/(W-1)`, `k=0..W-1`. This bounded crossfade overlaps visuals only; outgoing speech/motion is not continued. Do not subtract W from T, retime WAVs or move caption intervals. Draw captions and global progress/chrome once from Phase 04 time; blend scene-local titles with content, retain a compatible shared background, and prevent duplicate entrance dimming in opted-in transitions. Existing hard-cut paths remain unchanged. Unsupported layer separation, viewport/brand mismatch, asset readiness, duration or content compatibility fails explicitly. Matched-object handoff renders one compatible entity interpolating predecessor endpoint to successor state; reject incompatible primitive/asset/brand identities or conflicting actions. Arbitrary cross-template object matching, moving outgoing trajectories and unrestricted global state are deferred.

6. **Dependency-complete caching.** Preserve current audio keys; purely visual, camera, asset or transition changes must reuse unchanged valid audio. Each incoming clip owns its boundary pixels within the existing nonoverlapping global output partition, so current concat/mux can remain transport. Its key includes its compiled plan plus both adjacent scene content/handler and predecessor terminal-state/representation digests, transition window/policy and compatibility identity, resolved cues/camera/layout, global positions/total/captions, asset file+record hashes from **both** layers, visual brand, compiler/registry versions and implementation/tool identities. Edits to either neighbor invalidate every affected boundary consumer, including successor clips and scene-only exports, for specialized crossfades as well as composed handoffs. Assembly still binds ordered clips, actual WAVs and complete revision/provenance. Version/canonicalize serialized new plan identities; never reuse merely by entity ID or topic name.

7. **Phase 08 owns review/release invalidation.** Put compiled plans, pacing diagnostics and referenced asset records/bytes from both sides of a boundary into the existing portable render inventory. Extend the existing asset collector beyond LayeredAssetScene. Keep fresh exact-hash video/metadata/cover/evidence/rights checks and candidate-specific publish decisions. Include semantic visual content and meaning-changing continuity in the factual dependency projection, conservatively binding composed visuals and opted-in boundary semantics initially: visual claims can change while narration/claim IDs stay fixed. Test this explicitly, including crossfades between specialized templates. Preserve unrelated decisions only when the existing dependency rules actually permit it. Human pacing acknowledgements bind the exact report/artifact identity and remain distinct from release approval. Compiler, model, QC and successful tests cannot approve facts, rights, video or release. No publication integration is added.

8. **Explicit input source scope.** Normal input is a technology topic, **one or more user-approved official documents, GitHub references or technical articles**, audience/duration/creative instructions and an existing approved BrandProfile; user notes remain supported untrusted evidence. Reuse Phase 05 ResearchBundle/ClaimLedger and existing SSRF/DNS/redirect/byte/deadline controls. A repository root or moving ref produces an actionable `selection_required` outcome: retain the submitted repository/ref, explain the missing file paths and immutable revision approval, and ask the operator to supply/approve the exact relevant paths and full commit SHA. Suggestions may come from operator context, but unresolved paths/revisions must be labelled unknown and are not evidence. Initial 11D may stop there until the user provides approved commit-pinned file URLs; it must not claim to inspect unavailable files. Bind approval to exact repository/path/commit/retrieval scope before bounded ingestion, then preserve the real snapshot IDs/hashes. Any future bounded ref resolution/file-list retrieval needs explicit scope approval first; never infer approval of selected files from approval of a repository URL. No silent cloning, recursive crawling or fabricated commit pinning. Retrieval approval is separate from evidence review and media rights. Topic-only autonomous discovery remains optional Phase 14.

9. **Reuse the existing optional provider.** Content Director and Visual Director are logical prompt steps within the existing Director boundary, using `LLMProvider.generate({system,data,signal})` and `.accounting()`. Preserve current reviewed-evidence requirements and common `importDraft` validation for manual/mock/optional DeepSeek paths. Version prompts/schema/catalog/compiled inputs, candidate hashes and diagnostics; bound all stage attempts/time/tokens/spend under one invocation budget. Retain at most the existing one structural repair initially; raising it requires coordinated receipt/budget tests. No second provider interface, autonomous coding agent, mandatory framework or vision claim. Ollama/new hosted/vision adapters are optional future implementations of the same boundary; selecting one requires explicit configuration/authorization and compatible receipt/release-origin persistence. Keyless manual use remains first-class.

## Boundary pacing and human review

Phase 04 derives a diagnostic for every adjacent narrated scene, independent of whether it cuts, crossfades or hands off an object. At 24kHz with 800 samples/frame, report `gapSamples = (S_next*800 + speechStart_next) - (S_current*800 + speechEnd_current)`. Decompose it into outgoing WAV trailing inactivity, explicit end padding and incoming WAV leading inactivity; retain sample counts and milliseconds, scene IDs, WAV/text hashes, cue/caption bounds and detector/version identity. Activity endpoints are signal measurements, not word alignment. Report caption-free intervals separately; they need not equal audio inactivity.

Use the audit's existing city finding (about 900ms, including 597.333ms padding) as a pacing-review example, not a universal defect or evidence of mux drift. Proposed initial review policy flags a gap of **500ms or more**, any declared pause mismatch, and unexpected final decoded-audio discontinuity; thresholds are versioned review criteria, not authority to edit audio. Report every boundary even below the threshold. Structural A/V/sample failures fail QC. A long measured pause alone requires human review and is not automatically a failure or an intentional pause.

The human listens across each boundary and through the complete narrated MP4, checks whether the pause supports the explanation, and records deliberate / unintended / unresolved with a rationale. Explicit padding describes a mechanical cause, not editorial intent; WAV silence may be deliberate or unintended too. Check caption disappearance, abrupt visual re-entry, word clipping/repetition, unnatural silence and camera/asset handoff while listening. Unresolved flagged pacing remains review-needed and cannot be reported as accepted quality. Do not silently trim, stretch, splice or rewrite WAVs, fabricate word timing, shorten the measured timeline or add audio crossfades. If repair is requested, make an explicit script/hold/narration revision, measure again and invalidate dependent artifacts/reviews through the existing owners.

## Initial visual slice and product-quality acceptance

Start with node/link/token, labels/status and approved-image node content; flat groups and row/column/small-grid hints; finite appear/disappear, move-to-slot/follow-link, status/highlight and bounded focus. This is the **initial implementation slice, not the final product capability**. Compose approved existing local assets and relevant reusable 2D/2.5D motion, depth, parallax and camera primitives where registered and supported. Register finite semantic controls and preserve rights/file/record identities; do not expose arbitrary JSX/SVG/CSS, city-specific geometry or a new per-topic handler. Proposed caps: 8 entities, 12 links, 16 actions, 2 simultaneous moving tokens, 2 flat groups, 2 images, 24-character/two-line labels, plus existing scene/video/audio limits. No arbitrary expressions, code, raw markup/URLs, physics, graph solver or GPU 3D. Resource caps require actual mobile render verification and may be reduced transparently before the holdout freeze. True GPU 3D remains unimplemented.

11C must prove unchanged old VideoScripts and historical Director draft reads, multiple independent objects/actions, **executed** handler/schema/catalog parity, deterministic shuffled frame evaluation, measured cut/overlap arithmetic, no speech truncation/overlap, stable captions, both-neighbor cache invalidation, unchanged audio-cache reuse, complete artifact/asset-rights tracking and Phase 08 factual invalidation when visual meaning changes without narration changes. Test specialized→specialized and both composed↔specialized crossfade directions, compatible composed matched-object handoff, old hard cuts and typed unsupported combinations. Basic crossfade tests do not count as generic composition demonstrations.

Render at least three unrelated manually authored **composed** examples through the same handlers, including a **visually meaningful asset-backed composition** using reviewed existing assets and supported motion/depth/camera controls. A decorative image pasted beside rectangles is insufficient; the assets and motion must clarify the mechanism. Human playback evaluates mobile framing, readable scale, visual hierarchy, animation clarity, camera restraint, narration continuity and every flagged pacing boundary. Inspect before/during/after frames and listen to the complete real narrated MP4s; record pending human checks honestly. Specialized demos cannot substitute for generic tests.

Freeze schema/grammar, registry/compiler/render implementation and evaluation prompts before selecting the unseen holdout; record their hashes and make **no application source-code changes between holdout-topic renders**. Record honest unsupported outcomes; do not add a topic handler or silently substitute slides. Keep complete schema/catalog/prompt/example/evidence/feedback contexts inside documented byte/token limits, with the existing 96KiB Director request-data cap and adapter-specific limits checked before invocation. Use bounded capability exports without dropping required restrictions or evidence, and budget all stages/retries under one provider spend cap. 11D consumes the accepted compiler/catalog and repeats manual/mock source-grounded/security/budget evaluations; live paid calls require separate authorization.

## Alternatives and consequences

Extending 1.1.0 in place risks mutable contract semantics. A parallel VisualScript or second timeline creates competing authority. A new GPU engine/package does not solve semantic composition or narration continuity and lacks authorization/evidence. FFmpeg-only crossfades cannot resolve entity identity and would complicate clip/caption dependencies. Prefer the additive bounded Producer extension.

Trade-offs and remaining risks: held-pose crossfades may still feel static; content/chrome separation and pair compatibility across specialized handlers need implementation evidence; asset-backed layouts can exceed mobile space or frame cost; activity detection cannot decide editorial intent or word sync; neighboring dependencies reduce cache independence; conservative semantic fact invalidation can require more review; historical draft readers and growing catalog contexts need explicit version/budget tests. The initial grammar is bounded and does not promise every-topic coverage. Address these in 11C/11D acceptance, without introducing a second renderer or model adapter.

Stop after Phase 11C for human review; architecture acceptance never grants release approval.
