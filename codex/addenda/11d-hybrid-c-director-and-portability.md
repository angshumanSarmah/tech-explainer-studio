# ADDENDUM to existing Phase 11D — Hybrid C Director runtime, portability and asset intentions

**Read WITH** `codex/11d-source-guided-ai-visual-director.md`, not instead of it. Keep existing 11D requirements, prompt templates, security, research, schema/registry, preview, repair, tests and explicit STOP. The accepted ADR-019 remains authoritative; require review/acceptance of the Hybrid C proposal before implementing disputed additions. New image/video generation is **NOT part of 11D** (consistent with the original 11D OUT OF SCOPE).

## Additional product outcome

A non-developer can use the actual CLI **without Codex** to give a new topic and at least one explicitly approved source, choose a configured Director adapter/model (or external/manual mode), generate a source-grounded JSON storyboard, validate and render an MP4 with the existing pipeline, or import a valid external AI-authored JSON and render. Keep original 11D evaluation requirement for **multiple** approved sources and holdout; single-source usability does not waive multi-source acceptance evidence. The user may provide a GitHub repository root, but it becomes `selection_required` until explicit immutable file/revision approval; do not silently approve file scopes.

## Requirements

1. **Real operator CLI path.** Discover actual current CLI/Phase 05 ingestion/Phase 06 LLM/Phase 07 job/Phase 04 Producer. Add only missing orchestration, commands/config; do not invent a new backend engine. Expose an implementable path of source selection/review → Director planning → strict JSON → compile → measured narration → draft MP4 → existing review gates. Persist and resume review-needed states. Provide actual commands in report, not fabricated flags.
2. **Provider choice.** Reuse `LLMProvider.generate({system,data,signal})`/`.accounting()` (or actual compatible implementation) rather than a new adapter interface. Accept configured provider/model per Director job; Content and Visual may share the same selected model. Optional distinct content/visual selections only if real adapter and budget support them without duplicating workflows. No claim that Ollama/image/clip adapters already exist. Manual external JSON must be fully keyless.
3. **Director Kit export.** Produce one versioned portable ZIP, generated from the **real** current strict VideoScript schema, actual executable registry catalog/hard limits, BrandProfile, valid examples, exact prompt/version, approved source IDs/excerpts + review statuses (opt-in sharing), and listed available asset IDs. Include a manifest with schema/catalog/prompt/brand/source digests, supported output file format (`VideoScript JSON`), and a copyable instruction to any external Claude/ChatGPT/Codex. Privately sourced material must not be exported without explicit operator consent; include a metadata-only mode which does not pretend to ground unsupported claims.
4. **Manual import.** Accept external `.json` through the existing parser and every current validator/compiled draft/review gate; return JSON-path diagnostics and machine-readable feedback. Re-export the latest contract to repair incompatible drafts; do not add a permissive bypass or accept executed code. Demonstrate no credentials and no source modifications between two unrelated imports.
5. **Topic-aware proposed resource needs.** AI may propose semantic `AssetNeed` entries: purpose, scene/story beat, visual description, role/animation needs, alternative registered technique, and proposed production method (`registered`, `existing_asset`, `user_upload`, `ai_image`, `optional_ai_video`). Only use actually available methods for renderable scenes; unsupported media generation remains a future proposal, not an executable tool. Keep prospective needs in existing draft/job data where possible, or propose a small separate versioned planning contract if audit proves necessary. **Do not add fictitious asset IDs to VideoScript 1.2.0**, change 11C renderer or pretend an AI still image automatically has animatable layers.
6. **Prepare for hybrid production without implementing it.** An exported capability manifest should distinguish `installed`, `supported_manual`, `planned_disabled`, and `unsupported` states rather than advertise providers that are absent. AI video is disabled by default in proposed job settings. Media calls have their own approval later; Director planning API cost still requires a separately authorized cap.
7. **Cost and trust.** Enforce existing bounded request token/size, total invocation retries and cancellability (do not blindly raise 11D's allowed repair attempt count). Keep source excerpts untrusted, source upload privacy explicit, and no autonomous web browsing/publishing/asset rights approval.

## Additional 11D acceptance tests

- CLI: one authorized live provider test **if operator provides explicit key/budget**; separate offline mocked path; distinguish them in report. Render at least one unseen real multi-scene narrated MP4 without Codex creating per-topic JSON or modifying app source. If the authorized live path is unavailable, report it NOT TESTED, not PASS.
- Manual: export Director Kit, create external-compatible JSON from its real schema/catalog, import and render with no LLM key. Test malformed JSON, unsupported action, wrong source IDs, missing approved asset and hostile prompt text.
- Versioning: a kit generated at catalog N cannot silently validate against incompatible catalog N+1; show actionable stale-catalog errors or explicit recompilation/review. Historical 1.0/1.1/1.2 scripts and saved prior Director drafts remain intact.
- Honest quality: provide actual model-generated JSON, prompt/schema/catalog hashes, source provenance, token and observed/estimated cost, compiled plan and MP4. Compare manual vs live Director output on same approved sources and report creativity/visual limitations separately from validity.
- Asset needs: proposed-but-unresolved needs never pass as available assets or hidden paid-media generation. All release approval remains disabled until Phase 08 independent review.

**STOP after Phase 11D.** Do not implement image/video providers, H1, H2, dashboard, autonomous content discovery or publishing. Do not rewrite the original 11D prompt.
